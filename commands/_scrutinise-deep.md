# Phase D — `--deep`: exhaustive whole-run audit

Triggered by `--deep <run-slug>`. The mandate is **completeness, not speed**: find *every* defect across the entire surface an orchestrate run produced. Severities are `Critical` / `Warning` / `Suggestion`, as in the default pass. Root does steps 1–2 and 6 in both modes; **who runs steps 3–5 depends on `execution.agentMode`** (`_shared-analysis.md`):

- **`root-only` (default) — inside the one isolated scrutineer.** Dispatch a single `scrutineer` (`subagent_type: "craftsman:scrutineer"`) with mode `deep` and the full brief from steps 1–2 (every range, the changed-file set, floor hits, governing docs, plan docs, unticked criteria — facts only, never implementation rationale). It runs steps 3–5 **sequentially** — module by module, round by round — in its own fresh context. Same single-grant rule and **NOT ISOLATED** fallback as the default pass. No fan-out.
- **`subagents` — parallel fan-out.** Run steps 3–5 as written below, using `_shared-analysis.md`'s bounded fan-out pattern with this phase's tighter cap (12 modules, not ~15).

1. **Resolve the full surface (not a single diff).** From the run's execution rows: every unit, every merge SHA. Build the complete changed-file set (`git diff --name-only <merge-base>..<base-branch>` per merged unit — the run's base branch, never a hardcoded `main`). Re-read the originating plan doc(s) — the promised user-visible outcomes are the yardstick. Recall memory per area.
2. **Mechanical floor across the whole surface** — run the full Phase-0 check set over *every* touched module + range, plus any completeness pre-filter over `<run-base>...HEAD`. Every hit seeds the inventory.
3. **Exhaustive multi-dimensional review, capped.** **One comprehensive review per changed module**, briefed with its governing `docs/` reference and the complete defect-class checklist — correctness/logic · swallowed/mis-handled exceptions vs intended fail-closed · missing input validation · auth/permissions bypass · race/ordering · N+1 / missing pagination / perf · **stale contract between components** · dead/mis-set config/dangling flags · house-style conformance · simplification · reuse/duplication · **test-coverage gaps** on every new path · observability gaps. Each class is reported `FOUND`, `CLEAR`, or `UNPROVEN`; a class no reviewer is told to hunt is a class you miss. **The completeness hunt (#1 miss class)** is part of every module review: what the plan did not mention — a contract consumer left un-updated, a path not wired, an endpoint unguarded, a half-implementation. **Cap at 12 modules per round**, selected by changed-line count; log dropped modules and why. Specialist lenses (`security-auditor`, `consumer-tracer`, `standards-keeper`, `idiom-reviewer`, `ui-ux-reviewer`, `migration-reviewer`, `api-reviewer`, `dependency-auditor`, `performance-reviewer`, `observability-reviewer`) apply only to a surviving finding or an explicitly high-sensitivity module — dispatched as agents under `subagents`, applied by the scrutineer from their briefs under `root-only`. Unlike the default pass, `--deep` keeps `standards-keeper`/`idiom-reviewer`: consistency **across** units authored by separate implementer passes is exactly what no single-unit review can see.
4. **Adversarial verification (every finding, no exceptions).** Trace the cited lines, try to **refute** first, record only survivors. An unverified "defect" is noise — discard it.
5. **Loop-until-dry, capped.** Re-review only on findings at `Warning` or above. Stop when **two consecutive rounds add nothing new at that bar**, with a **hard ceiling of 4 rounds**; log what each round added, and say plainly if the cap — not dryness — stopped the loop.
6. **Check, emit, hand off (root).** Apply `/scrutinise` Phase 2 steps 1–2 to the returned findings (check against `file:line`, list every **Disputed** change with evidence, decide acceptance). Assemble **every surviving finding in the conversation** (class, severity, `file:line`, evidence, governing rule, fix task), sequenced correctness → security → conformance → reuse/simplification → coverage, plus one execution row per module needing fixes with a `### Tooling` manifest — then **auto-delegate persistence to `/plan`** (SlashCommand); `/plan` persists `docs/plans/scrutinise-<run-slug>.md` and registers the rows. Record memory. Report: isolation status, total findings by class + severity, rounds run until dry (or capped), modules dropped by the cap, the Disputed list, residual confidence (proven vs. couldn't-prove, e.g. runtime-only defects). Do **not** fix — next step **`/plan`**, then **`/orchestrate scrutinise-<run-slug>`**, then `/sync-docs`.
