> Canonical protocol for the per-unit execution loop (`/orchestrate` Phase C).
> `Read` only once actually about to run Phase X on a unit — the expensive half
> of shared machinery, split from `_shared-machinery.md` (kept light, read
> unconditionally) so a run that hasn't reached execution yet never pays for it.
> Not user-invocable.

## Phase L — Merge-only locking

A lock guards **the merge only**, never the work. Concurrent sessions may target the same base branch.

- Locking, base-branch discovery, worktrees, and merges are repository-local via `scripts/repo-exec.mjs` for each step's selected `project` — never assume `main`/`origin/main`/the controller checkout. Its atomic lock lives under that repository's Git-common directory (real session id, project, unit).
- Every unit works in its own worktree/branch (Phase X.2) — implement → gates → review → conflict-resolution are all **lockless**. Acquire the lock only for the final merge; release the instant it validates.
- Merge-time rules (Phase X.9d):
  - **Absent** → create lock, `checkout <base> && pull` + `merge --no-ff` + validate + push, delete lock immediately.
  - **Present, heartbeat < 30 min** → another session mid-merge. Don't wait/block — defer this merge, do other lockless work, retry next pass. Never lands → SKIPPED(locked), worktree left for later.
  - **Present, heartbeat > 30 min** → stale (crash); overwrite, log the reclaim, proceed.
  - **Release is mandatory + immediate** on every path (abort/conflict/error included) — never hold across a wait, build, gate, or approval.

## Phase X — Per-unit execution loop

For each unit, dependency order (shared/library → consumers → UI/presentation last):

1. **Claim** — atomically claim plan/unit via `scripts/claim.mjs` (real session id, plan, unit); an existing claim is BLOCKED/duplicate, never overwrite. Records the same transition in `scripts/tracker.mjs`'s structured ledger — the human-readable row is a concise projection. Release only after close-out or explicit PARKED.
2. **Worktree + branch** — `repo-exec.mjs action:"prepare"` (project, unit, slug, session id, optional worktree path). Discovers the real base branch, fetches its own remote, creates/reattaches the worktree. ALL edits/gates/review/conflict-resolution run there; base branch untouched until step 9. **No worktree → no edits.**
3. **Detect language & tooling** (tracker notes; never assume) — read repo markers, derive build/test/lint/format/typecheck commands from the project's own config (`package.json` scripts + lockfile manager, `pyproject.toml`/`tox.ini`, `go.mod`, `Cargo.toml`, `*.csproj`/`.sln`, `build.gradle`, `Gemfile`, `Makefile`). Missing command = skip + note, never invent. Pass any governing `docs/standards/` entry to the implementer.
4. **Delegate implementation** via Task to `implementer`: plan-doc path, worktree path (its only writable scope), task list, design spec, detected commands. Activate `scripts/scope.mjs` there first with the unit's exact manifest (incl. absolute `worktree_path`), mark scope-required. Implementer edits + runs local checks; does **not** commit. Then recall bounded plan memory: `printf '%s' '{"action":"recall","plan":"<plan>","unit":"<unit>","scope_id":"<scope_id>","query":"<task area>","max_items":6,"max_chars":3000,"summary_only":true}' | node "${CLAUDE_PLUGIN_ROOT}/scripts/plan-memory.mjs"` — treat as unverified hints, verify cited files in-scope, never widen the manifest from memory.
5. **Specialist gates** (read-only, parallel where multiple apply, per manifest). Critical/Major → back to implementer (counts toward retry budget); Minor → tracker notes. After each specialist (this step and step 8): `node "${CLAUDE_PLUGIN_ROOT}/scripts/log-specialist.mjs" <agent-name> <finding-count>`.
   - **Security** (mandatory on HIGH = auth/secrets/crypto/tenancy/permissions/external I/O): `security-auditor` on the diff.
   - **Deterministic floor:** `node "${CLAUDE_PLUGIN_ROOT}/scripts/gate-select.mjs" <merge-base>..<worktree-head>` once per unit — prints zero or more of `ui`/`migration`/`api`/`dependency`/`performance`/`observability`; dispatch the matching specialist with the diff. A floor, not a ceiling — escalate on your own judgment too if the script's heuristics miss something (e.g. embedded DDL).
     - `ui`→`ui-ux-reviewer`, `migration`→`migration-reviewer`, `api`→`api-reviewer`, `dependency`→`dependency-auditor`, `performance`→`performance-reviewer`, `observability`→`observability-reviewer` — all **advisory-only, never block the merge**, same as `idiom-reviewer` in step 8. An `api` breaking-change verdict still routes through `consumer-tracer`/`security-auditor` where those apply.
   - Any other manifest-named specialist beyond the standing panel (step 8) — e.g. `consumer-tracer` for a network/process-boundary contract.
6. **Simplify** — implementer tightens the diff (drop speculative abstractions, dead code, debug output). Minimal diff.
7. **GATE** (detected commands, in order) — format → lint → typecheck → tests, 100% (no skips added, no weakened assertions). **Coverage** where tooling exists: touched code below threshold (default 80%) = fail → add tests; no coverage tooling → note, don't skip silently. Failure #1 → raw output to implementer. Failure #2 → `build-doctor` triage → its `FIX FOR IMPLEMENTER` for the final retry. **Max 2 retries**, then PARK: `wip:` commit on `feat/<slug>`, `repo-exec.mjs action:"cleanup"` (removes the worktree; an unmerged branch survives), tracker → BLOCKED(failing gate + triage + branch). Never halt the whole run for one unit.
8. **Review — routed.** `review-router` (haiku) on the diff first; log via `node "${CLAUDE_PLUGIN_ROOT}/scripts/log-router.mjs" <verdict> "<reason>"` before acting — highest-volume review path, so this is where token cost is actually controlled.
   - **SKIP** (≤~120 lines, no new API/endpoint, no auth/permissions/migration/concurrency/contract change, manifest names no mandatory specialist) → GATE (step 7) already passed; skip the whole panel, note `reviewed: skipped(router)`.
   - **ESCALATE** → dispatch in parallel to the same diff: `code-reviewer` (correctness/security/maintainability), `standards-keeper` (audit mode — repo's own conventions), `idiom-reviewer` (simplification). Enforced here so `/scrutinise` never re-litigates a single unit's style later. `performance-reviewer`/`observability-reviewer` are NOT part of this standing panel — only when step 5 flags them.
     - **Blocking:** `code-reviewer` `VERDICT: REJECT`, or `standards-keeper` Critical/Major → implementer fixes → re-review. Max 2 rounds; unresolved → PARK as BLOCKED.
     - **Advisory-only, never blocks:** `idiom-reviewer` findings, `standards-keeper` Minor deviations — fold in the cheap ones this round, rest → tracker notes `reviewed: idiom-advisory(...)`. Step 5's specialist findings fold in the same way.
9. **Sync → resolve (lockless) → merge → cleanup** — commit all worktree changes. Before entering the primary checkout for the locked merge, release the worktree binding: `printf '%s' '{"action":"release","session_id":"<real session id>","project":"<id>","worktree_path":"<absolute worktree>"}' | node "${CLAUDE_PLUGIN_ROOT}/scripts/scope.mjs"`. Reactivate the next unit's scope before implementation resumes.
   - **a. Pre-merge sync (no lock):** `repo-exec.mjs action:"sync"` — fetches/merges the base ref; conflicts surface in the worktree.
   - **b. Resolver:** clean → skip to c. Conflict → resolve in the worktree (implementer; 2nd attempt gets `build-doctor` triage first), re-commit, **re-run the full gate (step 7)**. Max 2 attempts; still bad → `merge --abort`, PARK BLOCKED("merge conflict"), branch kept.
   - **c. Pre-merge guard:** confirms the worktree is clean and the branch carries commits beyond the discovered base. **Acceptance check here, while the worktree still exists to fix things in:** verify every `- [ ] [unit:<this unit or scope_id>]` line in `.craftsman/acceptance.md` against the worktree's diff and tests; tick it only if the code genuinely satisfies it, otherwise go back to step 4. Step 11's tracker → MERGED is mechanically refused while any of them is unticked.
   - **d. Locked merge:** `repo-exec.mjs action:"merge"` — atomically locks, merges into the base branch, validates ancestry, pushes if configured, releases the lock on every path. **Mechanically re-verifies the project's own detected test command inside the worktree before merging** (`repo-exec.mjs`'s `verifyGateBeforeMerge`) — a failing test blocks the merge outright regardless of what step 7 reported; disable only via `craftsman.config.json`'s `repoExec.verifyTestsBeforeMerge: false` or `stopGate.enabled: false`, never per-call. Base advanced → sync and retry.
   - **e. Cleanup (automatic):** a successful `merge` removes the worktree, prunes, and deletes the branch once it is proven to be in the base branch; its output carries `cleaned: true`. `cleaned: false` with a `cleanup_error` → fix the cause and run `repo-exec.mjs action:"cleanup"` yourself; the Stop gate blocks while that merged worktree survives. Never pass `cleanup: false` normally.
10. **Suite hygiene** — pre-existing failures unrelated to this unit: mechanical/clear → `build-doctor` triage → implementer as a separate `test:`/`fix:` commit folded into the same merge; non-trivial → PENDING follow-up row. A unit never merges leaving the suite red.
11. **Close out** — lockless: tracker row → MERGED (note the merged SHA). **This is the unit's "done" check:** `tracker.mjs` refuses MERGED/COMPLETE while any of the unit's `[unit:<id>]` acceptance criteria is unticked, and the refusal lists them. Refused → not done: satisfy them or PARK/BLOCK with the reason; never tick to get past it. MERGED → COMPLETE is automatic once its criteria and all untagged ones are ticked; mirror it in `TRACKER.md`. Then release the claim (`scripts/claim.mjs`, same session id), record memory. A PARKED/BLOCKED unit keeps its claim until the hand-off records the surviving branch + recovery owner.
12. **Unit hand-off and context reset** — write a hand-off before leaving: `printf '%s' '<JSON>' | node "${CLAUDE_PLUGIN_ROOT}/scripts/handoff.mjs"` (must include the real `session_id`). Include plan, unit id, merged/blocked status, changed files, acceptance and gate results, unresolved risks, exact next unit. Then invoke `/compact` — **mechanically required, not optional**: `handoff.mjs` marks the session compact-required as soon as the hand-off is on disk (as does `tracker.mjs` on a transition into a terminal status, which covers PARKED/BLOCKED exits that never reach a hand-off), and `compact-gate.mjs` hard-blocks every other tool call until a real `/compact`/`/clear` fires. After compaction, re-read only the tracker, the next unit's `scope.read`+`scope.docs`, and its task text. Phase complete → use `/orchestrate`'s phase hand-off protocol, begin the next phase fresh.

## Memory before context reset

Pass only compact, post-gate entries in the hand-off's `memory_entries` array — categories like `decision`, `dependency`, `contract-consumer`, `tooling-gotcha`, `review-finding`, `acceptance-result`, `unresolved-risk`; include scope id, source files, commit identity, `verified`/`unproven` status. **Every entry needs `tags`** (≥1 — untagged records are rejected outright) and a **summary ≤220 chars** — one terse fact, never a paragraph. Recall never blanket-dumps: no real `query` → nothing returned; a real one only surfaces term-matching records. Best-effort — a malformed entry is logged, never blocks the reset. Recall for the next unit happens after its scope activation and never changes that scope.

## Finalization (calling command's close-out)

- **Worktree sweep (mandatory, mechanically checked at Stop):** `git worktree list` should show only the primary checkout. Unmerged (parked) → `repo-exec.mjs action:"cleanup"` (worktree removed, branch kept), and make sure a BLOCKED/PARKED/SKIPPED row names the branch. Merged worktrees are removed **mechanically**: every Stop and every SessionStart runs `worktree-sweep.mjs`'s `all_merged` sweep over the whole repository, whatever created the worktree (repo-exec, a hand-run `git merge`, earlier sessions, crashes, Claude Code's `.claude/worktrees/` once their session has ended). It removes only worktrees that are merged into the base branch, clean, not the caller's cwd, and not locked by a live session — never forced. `stop-gate.mjs` then hard-blocks completion if a worktree **this session prepared** (ledgered by `prepare`, retracted by `cleanup`) is merged but survived the sweep, naming the reason (e.g. uncommitted changes) to resolve. To inspect manually: `printf '%s' '{"action":"list"}' | node "${CLAUDE_PLUGIN_ROOT}/scripts/worktree-sweep.mjs"`.
- **Integration build** (if the project defines one): run once on the merged base; failure → BLOCKED follow-up row (merged code stays). No build step → note it.
- **Tracker consistency:** delegate `phase-tracker` to confirm every touched row reflects its true merged/parked state before COMPLETE.
- **Memory compaction:** after the phase hand-off, only when a plan has accumulated more than one entry per unit/category, run `printf '%s' '{"action":"compact","plan":"<plan>","project":"<project>"}' | node "${CLAUDE_PLUGIN_ROOT}/scripts/plan-memory.mjs"` — replaces history with bounded summaries, doesn't alter tracker/scope/claim/acceptance state. (Also runs automatically, rate-limited, from SessionStart — see `session-context.mjs`.)
