# ARCH engine — enforced rules

- **ARCH-ENGINE-01** [superseded by ARCH-ENGINE-12] execution.engine MUST be one of workflow | subagent | root, default "workflow"; an unavailable workflow runtime falls back to "subagent", never silently to "root"; "root" is explicit opt-in only — check: config default + /auto launch fallback test — cite: craftsman.config.json:3-6
- **ARCH-ENGINE-02** [decided] The workflow default MUST NOT land until a 1-unit spike records hooks firing in agents, worktree-keyed scope activation, the quality gate, repo-exec prepare/merge, a tracker transition and the park path — check: spike evidence in the plan's acceptance criteria — cite: docs/plans/autonomous-e2e-loop-evidence.md:34-55
- **ARCH-ENGINE-03** [decided] A workflow script MUST only orchestrate: no fs/shell, no import(), no Date.now/Math.random/new Date(); all repo work runs in agents via the existing scripts — check: wiring.test.mjs lints workflows/*.js — cite: scripts/wiring.test.mjs:98-134
- **ARCH-ENGINE-04** [decided] One unit protocol: agents/unit-runner.md drives both the workflow agent() prompts and the subagent fallback — check: wiring test, both engines reference the same file — cite: scripts/wiring.test.mjs:149-161
- **ARCH-ENGINE-05** [decided] Each unit runs an implementer agent then a separate fresh reviewer agent; the script enforces at most 2 fix rounds, then PARKs — check: workflow loop bound + test — cite: workflows/run.js:99-121
- **ARCH-ENGINE-06** [decided] Unit agents MUST return schema JSON {unit, status, evidence, sha|pr, parked[]}; root context holds only tracker state, the plan path and per-unit summaries of at most 2k tokens — check: every agent() call passes a schema — cite: workflows/run.js:17-45
- **ARCH-ENGINE-07** [decided] An open decision mid-run MUST PARK the unit with a structured decision, never a default, and leave its dependants PENDING — check: tracker.test.mjs decision field — cite: scripts/tracker.mjs:46-78
- **ARCH-ENGINE-08** [decided] /plan MUST refuse a unit whose scope.read + scope.docs + task text exceeds execution.unitContextBytes (default 122880) — check: plan dry-run test — cite: scripts/arch-check.mjs:152-185
- **ARCH-ENGINE-09** [superseded by ARCH-ENGINE-17] Units run sequentially in plan-graph order (pipeline, not parallel) until parallel scope isolation (ARCH-STATE-03) is spike-proven — check: workflows use pipeline() — cite: workflows/run.js:166-183
- **ARCH-ENGINE-10** [decided] For autonomous runs root-context-first supersedes the total-token rationale for root-only mode — check: README and CHANGELOG wording — cite: CHANGELOG.md:21-25
- **ARCH-ENGINE-11** [decided] scripts/workflow.test.mjs MUST be renamed loop-smoke.test.mjs so "workflow" means only Claude Code workflows — check: file absent — cite: scripts/loop-smoke.test.mjs:1-48
- **ARCH-ENGINE-12** [decided] execution.engine MUST be one of workflow | subagent | root, default "workflow"; under /auto an unavailable workflow runtime falls back to "subagent" (one unit-runner per unit, granted by the /auto invocation, ARCH-AUTO-06), never silently to "root"; a standalone /orchestrate stays root-only (ARCH-ENGINE-10), so there an unavailable workflow is reported and the unit protocol runs in root; "root" is explicit opt-in only — check: config default is workflow + agent-mode-guard blocks a unit-runner outside a live /auto — cite: scripts/agent-mode-guard.mjs:91-123
- **ARCH-ENGINE-13** [decided] workflows/run.js groups units by feature and after a feature's last unit makes one agent() call for land-feature with the RESULT schema; the protocol is commands/_features.md passed as protocolText, with a one-line role pointer in agents/unit-runner.md — check: wiring.test.mjs — cite: workflows/run.js:17-45
- **ARCH-ENGINE-14** [superseded by ARCH-ENGINE-18] A plan without features: runs the single-feature path unchanged; a feature holds at most planning.featureUnitCap (default 8) units and plan-graph refuses more, or a depends_on into a later feature — check: plan-graph.test.mjs — cite: scripts/plan-graph.mjs:6-34
- **ARCH-ENGINE-15** [decided] One session owns a feature through claim.mjs with unit "feature:<id>"; cross-session decisions live in the plan doc's ## Decisions section, fed from PARKED decisions and plan-memory list-decisions — no message channel — check: claim.test.mjs, plan-memory.test.mjs — cite: scripts/claim.mjs:7-10
- **ARCH-ENGINE-16** [decided] Two or more units of one feature run concurrently (a wave) only when execution allows at least that many sub-agents (the per-session cap, root-only by default, no nested agents), plan-graph finds units with no depends_on between them and disjoint scope.write, and the wave spike has passed; workflows/run.js dispatches a wave with parallel() from the root and the units of a wave never share a worktree — check: plan-graph.test.mjs wave cases, wiring.test.mjs — cite: workflows/run.js:166-183
- **ARCH-ENGINE-17** [decided] Units run sequentially in plan-graph order inside the feature worktree; the only concurrency is an ARCH-ENGINE-16 wave, and workflows/run.js carries the feature's worktree_path from the first unit's result to every later unit, so agents/unit-runner.md prepare reattaches instead of creating — check: workflows use pipeline() outside waves, wiring.test.mjs — cite: workflows/run.js:142-183
- **ARCH-ENGINE-18** [decided] A plan without features: is one implicit feature (id = slug) on the feature-worktree and land-feature path (ARCH-LAND-13, ARCH-LAND-18); a feature holds at most planning.featureUnitCap (default 8) units and plan-graph refuses more, or a depends_on into a later feature — check: plan-graph.test.mjs implicit-feature and cap cases — cite: scripts/plan-graph.mjs:6-34
- **ARCH-ENGINE-19** [decided] A runner that needs the network returns NEEDS_NETWORK with network_action and records nothing (ARCH-LAND-19); workflows/run.js then stops without blocking or parking and returns needs_network {unit, action, resume}, and a relaunch skips what args.landed / featuresDone name and resumes at args.resume / featureWorktrees; root builds run args only with scripts/run-args.mjs (one run per project, in plan-graph order) and runs the network steps outside the sandbox per commands/_network.md — check: engine.test.mjs NEEDS_NETWORK cases, followups.test.mjs run-args case — cite: workflows/run.js:210-283
- **ARCH-ENGINE-20** [superseded by ARCH-ENGINE-22]
- **ARCH-ENGINE-21** [decided] A code unit follows red-green: the implementer writes a failing test for each testable [unit:] criterion before the change and the reviewer refuses a unit whose new test never failed; verification before completion means fresh gate output in the unit's evidence — check: unit-runner-tdd.test.mjs red-run evidence wording on both review paths, unit-runner.md steps, workflows/run.js review prompt — cite: agents/unit-runner.md:16
- **ARCH-ENGINE-22** [decided] Project tools enter craftsman only through config adapters, each skipped silently when its binary or config is absent: stopGate.commands prefers "justfile": "just check" when a justfile exists; security.check runs gitleaks with the built-in scanner as fallback; docs.checks (empty by default) runs at the verification point; pre-commit run --all-files runs once at the verification point and never per unit (git's own commit hook is left as the repo configures it); /init never writes a justfile, pre-commit config or CI workflow — check: tool-slots.test.mjs absent-tool skip, init.test.mjs writes none of them — cite: craftsman.config.json:113-148
