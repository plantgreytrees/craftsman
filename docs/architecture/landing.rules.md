- **ARCH-LAND-31** [decided] /auto MUST NOT use push --force, push -f, reset --hard, worktree remove --force or history rewrites (filter-repo, rebase of a pushed shared branch); the single exception is git push --force-with-lease to the unit branch this run is bound to (feat/ or feature/) or a feature/<plan>-<id> branch of this plan, written as `src:refs/heads/<own>` with one colon, to a remote word with no path separator (never `.`, `..`, a path or a URL), as an unquoted top-level push (never inside bash -c or any quoted string), with no `$`, backtick or backslash and no `alias` word in the command, no config-override option or GIT_* prefix, never base; the plan glob also matches another run of the same plan and any plan whose slug begins with `<plan>-`, which is the tracked row lease-glob-anchoring; the Bash-tool force block that enforces this is a best-effort text scan and defense in depth, not a proof: it refuses the literal, config-carrying and xargs/parallel forms it can read, and it does not check history rewrites at all (filter-repo, rebase: an /auto instruction only), and it cannot read command strings assembled from adjacent quoted pieces, flags built by expansion, a git word that is not literal, plumbing (send-pack), remote deletes, or programs it cannot read (make, npm, a script file); base protection rests on the remote's branch protection and the approval gate (ARCH-LAND-28), and a structural word-level rewrite of the block is a tracked follow-up (force-block-wordlevel) — check: force-block.test.mjs lease allowed and refused forms, config-carrier and xargs refusals; pre-guard-narrow.test.mjs lease cases — cite: scripts/lib/force-block.mjs:1-173
