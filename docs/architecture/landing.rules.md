# ARCH landing — enforced rules

- **ARCH-LAND-01** [superseded by ARCH-LAND-22]
- **ARCH-LAND-02** [superseded by ARCH-LAND-08]
- **ARCH-LAND-03** [decided] A parent's submodule pointer bump MUST be an explicit parent unit after the submodule unit lands; repo-exec stays single-repo — check: plan-submodules.test.mjs — cite: scripts/lib/plan-submodules.mjs:1-89
- **ARCH-LAND-04** [superseded by ARCH-LAND-07]
- **ARCH-LAND-07** [decided] Only registered projects are touched; submodules come only from gitlinks (mode 160000, `git ls-files -s`) in a registered root's index, plus a refuse-only read of the workspace-root index; never by scanning directories — check: plan-submodules + plan-graph tests — cite: scripts/lib/plan-submodules.mjs:11-47
- **ARCH-LAND-05** [superseded by ARCH-LAND-23]
- **ARCH-LAND-06** [decided] Conflicts, ff-only failures, rejected pushes and pr auto-merge errors PARK with a Phase C decision; nothing else stops landing — check: repo-exec errors — cite: scripts/repo-exec.mjs:222-251
- **ARCH-LAND-08** [superseded by ARCH-LAND-18] Units land by repo-exec merge onto their target (base or feature/<plan>-<id>) in plan-graph order; a finished feature lands by repo-exec land-feature (detached temp worktree, base merged in, gate re-run, --no-ff, push; feature lock, then base) — check: repo-exec.test — cite: scripts/repo-exec.mjs:278-310
- **ARCH-LAND-09** [decided] A feature branch is pushed at creation, never inferred as base, never swept — check: repo-exec, sweep tests — cite: scripts/repo-exec.mjs:31
- **ARCH-LAND-10** [decided] Feature landing ships only after a spike shows feature merge, sync, land-feature, a conflict park and a sparing sweep — check: spike evidence — cite: docs/architecture/engine.rules.md:12
- **ARCH-LAND-11** [decided] A submodule bump shares its submodule steps' feature — check: plan-submodules.test — cite: scripts/lib/plan-submodules.mjs:73-86
- **ARCH-LAND-12** [decided] pr mode: unit PRs → feature; one feature PR → base — check: repo-exec.test — cite: scripts/repo-exec.mjs:347-379
- **ARCH-LAND-13** [decided] A feature session owns exactly one long-lived worktree: repo-exec prepare {slug "<plan>-<id>", branch feature/<plan>-<id>} under <main checkout>/.worktrees, anchored at the main checkout root and never at the session's linked .claude/worktrees directory; every unit of the feature reattaches to it, and .claude/worktrees/ is gitignored — check: repo-exec.test.mjs reattach and linked-worktree anchoring — cite: scripts/repo-exec.mjs:44-56
- **ARCH-LAND-14** [decided] A unit lands by repo-exec land-unit inside the feature worktree: gate re-run, feature branch checked out, merge --no-ff of the unit branch, feature branch pushed, unit branch deleted; a conflict PARKs (ARCH-LAND-06) and a PARKED or BLOCKED unit keeps its branch and leaves the feature branch checked out clean for the next smoke gate — check: repo-exec.test.mjs land-unit cases — cite: scripts/repo-exec.mjs:196-259
- **ARCH-LAND-15** [decided] A wave unit (ARCH-ENGINE-16) runs in a short-lived worktree branched from the feature branch, lands back through land-unit and is removed at once; the feature keeps its single long-lived worktree — check: repo-exec.test.mjs wave worktree cleanup — cite: scripts/repo-exec.mjs:392-416
- **ARCH-LAND-16** [decided] Feature prepare refuses while the plan doc or its parent chain differs from origin/<base>; generated rollups are excluded because every tracker transition rewrites them locally; /orchestrate Phase A lands the plan docs through /craftsman:merge first, and a mid-run plan amendment trips the gate again at the next prepare — check: repo-exec.test.mjs plan-gate refusal — cite: scripts/repo-exec.mjs:126-156
- **ARCH-LAND-17** [superseded by ARCH-LAND-24]
- **ARCH-LAND-18** [superseded by ARCH-LAND-25]
- **ARCH-LAND-19** [decided] A unit runner holds no credentials and the sandbox is never loosened (no allowlisted credential dirs, no tokens passed in): repo-exec fetches and pushes only where origin is reachable (input.network, CRAFTSMAN_NETWORK, else one `ls-remote` probe); offline it reads origin/<base> only when root's `network fetch` is younger than repoExec.offlineMaxFetchAgeMinutes (default 120), queues every push as a plain pinned-sha refspec (never forced) for root's `network drain`, and raises NeedsNetwork (exit 3, JSON {needs_network, action}) before any side effect when it needs a fresh fetch or the host API (pr mode); credentials are scrubbed from every message, and a drained push origin refuses PARKs (ARCH-LAND-06) — check: network.test.mjs no-credentials, queue-and-drain and stale-fetch cases — cite: scripts/lib/network.mjs:48-56
- **ARCH-LAND-20** [decided] repo-exec attaches a detached submodule checkout only when HEAD equals origin/<base> and local <base> is absent or an ancestor of HEAD (ref moved forward by compare-and-swap, then checked out, so no file changes); anything else is refused naming the reason; repoExec.attachDetached false turns it off — check: followups.test.mjs detached case — cite: scripts/repo-exec.mjs:73-98
- **ARCH-LAND-22** [decided] /auto is standing approval to commit, branch, merge base into feature branches, push the run's own feature and unit branches to origin, and clean up worktrees and branches in every registered project; merging or pushing to base, publishing the tracker to base, opening a PR and any post to an external service happen only after ARCH-APPROVAL-04, except landing the plan docs whose questions the owner answered in Phase A (that answer authorises the docs-only push ARCH-LAND-16 needs) — check: auto-command.test.mjs, repo-exec.test.mjs land-feature refuses without an approval record — cite: commands/merge.md:89-94
- **ARCH-LAND-23** [decided] /auto MUST NOT use push --force, push -f, reset --hard, worktree remove --force or history rewrites (filter-repo, rebase of a pushed shared branch); the single exception is git push --force-with-lease to a branch this run created (feature/<plan>-<id> or a unit branch it claimed), never base and never another session's branch — check: pre-guard.test.mjs force-with-lease own-branch allowed, base and foreign branch refused, plain --force refused — cite: scripts/lib/force-block.mjs:1-127
- **ARCH-LAND-24** [decided] tracker publish (ARCH-TRACKER-11) pushes to base only inside an approved land (ARCH-LAND-22) or a /sync-docs --tracker the owner runs; config tracker.publish is off|on-approve (default on-approve), limited to generated pathspecs under the force block; a protected base logs tracker_publish_rejected and continues — check: tracker.test.mjs no publish push before approval — cite: scripts/repo-exec.mjs:568-670
- **ARCH-LAND-25** [decided] A unit lands by repo-exec land-unit inside its feature's worktree onto feature/<plan>-<id> (ARCH-LAND-14), in plan-graph order; a finished feature lands by repo-exec land-feature (detached temp worktree, base merged in, gate re-run, --no-ff, push; feature lock, then base) — check: repo-exec.test land-unit and land-feature cases — cite: scripts/repo-exec.mjs:568-670
- **ARCH-LAND-26** [decided] land-feature and merge MUST run a non-mutating retire check after promotion: each plan whose rows are all COMPLETE or CANCELLED logs doc_retire_candidate {plan, referrers}; the check never fails, parks or retires a landing, and retirement stays ARCH-DOCS-09 — check: repo-exec.test.mjs candidate event, landing unaffected by a scan error — cite: scripts/repo-exec.mjs:664
- **ARCH-LAND-27** [decided] An approved land whose base moved since the page re-merges base into the feature, re-runs the gate and lands when green and conflict-free with the approved head_sha as an ancestor; a conflict, a red gate or a feature head other than the approved one PARKs and requests a new approval page — check: repo-exec.test.mjs moved-base land, conflict park, head mismatch — cite: scripts/repo-exec.mjs:568-670
