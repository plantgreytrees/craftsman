# ARCH safety — enforced rules

- **ARCH-SAFETY-01** [decided] Outside-root writes, deletes and credential reads MUST be left to the Claude Code sandbox; craftsman adds no guard for them — check: pre-guard.mjs names no outside-root write, delete or credential-read rule; /craftsman:init recommends the sandbox settings — cite: scripts/pre-guard.mjs:2-6
- **ARCH-SAFETY-02** [decided] A safety hook (pre-guard, agent-mode-guard, orchestrate-scope-guard) MUST fail closed: with node missing hooks/run.sh exits 2 with "node not found, guards cannot run", and any exit other than 0 or 2 from the hook itself is a denial too; the one exception is orchestrate-scope-guard on a UserPromptSubmit event, where exit 2 would erase the prompt, so any failure there says the prompt was not checked and exits 0; a safety hook also starts with NODE_OPTIONS cleared — check: launcher.test.mjs — cite: hooks/run.sh:54-89
- **ARCH-SAFETY-03** [decided] A safety hook MUST also fail closed in process: bad JSON, empty stdin, an uncaught error or a failed context load exits 2 naming the guard; onFailure "block" in hooks.json (Claude Code 2.1.295+) is only a second layer — check: pre-guard.test, agent-mode-guard.test and orchestrate-scope-guard.test fail-closed cases — cite: scripts/pre-guard.mjs:27-37, scripts/agent-mode-guard.mjs:59-69, scripts/orchestrate-scope-guard.mjs:75-85
- **ARCH-SAFETY-04** [decided] Advisory hooks (quality-gate, stop-gate, builtin-skill-context) MAY fail open on bad input but MUST say so once per session, and SessionStart MUST report whether the guards are on or off and why — check: core.test.mjs advisory cases, session-context.test.mjs reason strings — cite: scripts/lib/core.mjs:680-713, scripts/session-context.mjs:34-48
- **ARCH-SAFETY-05** [decided] Only CRAFTSMAN_SAFETY=off in the user's environment MUST disable the safety hooks; CRAFTSMAN=off, .craftsman/off and enabled:false switch off the quality, doc and tracker machinery only, and a tool call is refused, by token matching, when it would create .craftsman/off, a grant, marker, goal token or scope file (by write, mkdir, ln or a symlinked directory, judged by real path, a dangling link being followed to where a write would land and a link made by ln being judged by what it points at, and read as shell words: quotes removed, cd tracked; a command the parser gives up on, such as a subshell, is refused when it can write and names craftsman state; a directory destination is judged as DIR/name for each source, a directory source of cp -r, rsync or mv is listed (bounded) and every file under it is judged at its destination, an in-place edit (sed -i, --in-place, awk -i inplace, ed, patch) is judged by the file it names, an archive unpacked into a directory is judged by that directory (tar and unzip are read exactly only in an allowlist of spellings: argument-free option clusters and -C / --directory / -d, with every -C of a chain judged relative to the one before; any other spelling leaves the destination unknown and the command is refused outright, whatever it names; there is no list-only skip for unzip (every list of letters that write nothing was wrong in some review, so unzip -l a.zip is refused like any other spelling off the allowlist); awk in-place as -i inplace, -iinplace, --include inplace and --include=inplace), find -delete and -exec rm are judged by the protected files under each start root that the -name tests select, and removing or moving a directory that holds one of these counts as writing it), edit hooks.json, .git/config or .git/hooks/**, the config keys enabled, protectedPaths, docWriteGuard, execution.agentMode, execution.engine, stopGate, worktrees, repoExec.approval.required and planning.featureBranches (the two that switch the human approval gate on, scripts/lib/approval-gate.mjs approvalRequired) (of craftsman.config.json and of craftsman.project.json, the optional project override that loadConfig merges after it) (what the sweep may remove, ARCH-SAFETY-07), or the hook-disabling keys of .claude/settings*.json (hooks, disableAllHooks, sandbox, permissions.defaultMode, the craftsman plugin entry, and the CRAFTSMAN*, NODE_OPTIONS, NODE_PATH, PATH, LD_PRELOAD, LD_LIBRARY_PATH, DYLD_*, CLAUDE_PROJECT_DIR, CLAUDE_CODE_SESSION_ID and CLAUDE_PLUGIN_ROOT env keys), all compared case-folded, or run toggle.mjs off or doc-write.mjs on in any invocation outside a craftsman command (the scripts refuse for themselves without the owning command record for the session and without a one-shot, 60-second nonce that pre-guard leaves, for the session of the tool call, only when it lets a plain `node …/doc-write.mjs on`, `toggle.mjs off` or `goal-token.mjs` command through and every later check has passed, so no spelling of the command line and no other process reaches them (the nonce is never skipped, not by the script's own environment and not by a file; under CRAFTSMAN_SAFETY=off no guard runs, so doc-write.mjs on is a no-op that writes nothing, while toggle.mjs off and goal-token.mjs keep refusing and doc-retire.mjs always requires the grant (nothing is skipped on the strength of CRAFTSMAN_SAFETY, so /sync-docs --archive needs a session with safety on); a permission prompt that follows the nonce is not covered, it expires after 60 seconds); a model Skill call of a doc writer counts as a record, only toggle needs the user's typed command; and a command that sets CLAUDE_CODE_SESSION_ID, CLAUDE_PROJECT_DIR or CRAFTSMAN_SAFETY by assignment, read, printf -v, declare, export or env is refused, as is read or printf -v of HOME or XDG_CONFIG_HOME before a hook-running git command, so the id and the state root those checks trust cannot be borrowed from another session; a plain read of them is allowed) (a linked worktree's session keeps its scope manifests, command records and grants in the main checkout's .craftsman, shared through the git common dir, so those paths are judged there too, for a write, a redirect and a removal) (and scope activation honours a manifest whose write list can reach hooks.json, the config or a settings file (by name, directory, glob or a symlinked directory, judged by where it leads) only after /orchestrate or /auto); the guard reads shell words and runs no shell, so files written by an interpreter (`node -e`, `python3 -c`, a pipe into `sponge`) and command text built at run time are not read and stay with the sandbox (ARCH-SAFETY-01), and so does what an archive unpacked into the project root, or a patch that names its files only inside itself, contains, a variable set by `for NAME in`, `select NAME in` or a brace-built name (the session-id forms gain nothing: the nonce belongs to the real session), awk in-place named by its include path (`gawk -i …/inplace.awk`), the kept false positive that refuses prose naming a setter word next to a safety variable, and options taken from the environment (UNZIP, UNZIPOPT, TAR_OPTIONS), which the guard does not see; archive and option spellings are best-effort, and the sandbox, not this guard, is the boundary for them; and the quality gates (the tracker's MERGED acceptance gate, `baseline`, `snapshot`) honour CRAFTSMAN=off in a script's own environment, because it is the user's documented switch for the quality side, so a command can set it for one script and the quality gates are not a security boundary — check: pre-guard.test.mjs self-disable table, core.test.mjs safetyEnabled, safety-cites.test.mjs — cite: scripts/lib/core.mjs:621-623, scripts/pre-guard.mjs:678-694, scripts/pre-guard.mjs:1438-1528, scripts/pre-guard.mjs:1559-1569, scripts/scope.mjs:166-172
- **ARCH-SAFETY-06** [decided] Stop and SessionEnd MUST report unpushed work in the main checkout and every worktree (uncommitted changes, stashes, branches ahead of or without an upstream, detached commits) from local refs only; Stop blocks on it only when stopGate.blockOnUnpushed is true, and the Stop that ends a turn after a block still reports it — check: unpushed.test.mjs, stop-gate.test.mjs, session-end.test.mjs — cite: scripts/lib/unpushed.mjs:29-73, scripts/stop-gate.mjs:26-34, scripts/stop-gate.mjs:51-85, scripts/stop-gate.mjs:415-418, scripts/session-end.mjs:6-26
- **ARCH-SAFETY-07** [decided] The worktree sweep MUST be evidence-based and reversible: a branch counts as merged only into a remote-tracking base ref, a worktree holding non-disposable ignored files or living under .claude/worktrees (unless worktrees.sweepClaudeWorktrees) is kept, and every branch deletion is logged with its sha first — check: worktree-sweep.test.mjs — cite: scripts/worktree-sweep.mjs:46-52, scripts/worktree-sweep.mjs:173-184
- **ARCH-SAFETY-08** [decided] Safety MUST NOT depend on git anchoring: outside a git repository the protected-path, scope, dispatch and fail-closed checks stay on, and only the quality, doc and tracker machinery goes off, writing no state — check: pre-guard.test.mjs non-git cases, core.test.mjs safetyEnabled — cite: scripts/lib/core.mjs:603-623, scripts/pre-guard.mjs:1073-1077
- **ARCH-SAFETY-09** [decided] The mod MUST submit a goal only if craftsman wrote it this session: /instruction and /auto record a token through scripts/goal-token.mjs (name, mtime and a SHA-256 of the content, per session, minted only after one of those commands ran, and a Bash command that runs goal-token.mjs is refused outside them; the file's realpath dirname must equal the realpath of this checkout's or the main checkout's .craftsman/instructions, so a goal file saved in a linked worktree or by state-write.mjs in the main checkout mints while a symlink out, an unrelated copy or a file elsewhere is refused; the token goes under the minting checkout's session dir, so from a linked worktree the mod, which reads goal file and token from one root, may still fall back to the paste path: it fails closed, UX only) and hooks/register.js launches only a goal file that matches one, otherwise it names the file and does not submit — check: register.test.ts, goal-token.test.mjs — cite: hooks/register.js:26-60, hooks/register.js:132-170, scripts/goal-token.mjs:17-51
- **ARCH-SAFETY-10** [decided] Post-hoc detection MUST report, never replace the guard: SessionStart records the hash of every guarded doc, Stop reports guarded docs that changed without a doc-guard edit allow (a Read does not count; read from the root state dir even while a unit scope names another root), also on the Stop that ends a turn after a block (stop_hook_active), and /craftsman:init only offers (diff first, nothing written without a yes) to merge sandbox settings — check: doc-snapshot.test.mjs, stop-gate.test.mjs, settings-merge.test.mjs, init.test.mjs — cite: scripts/lib/doc-snapshot.mjs:19-56, scripts/stop-gate.mjs:51-85, scripts/lib/settings-merge.mjs:38-52
- **ARCH-SAFETY-11** [decided] A filter in front of pre-guard MAY skip it only where it cannot act: hooks/run.sh skips node for Read, Glob and Grep only when no scope or scope-required file exists for the session, the call names nothing protected-looking, and no project config overrides protectedPaths, in any file loadConfig merges (craftsman.config.json and craftsman.project.json, the list PROJECT_CONFIG_FILES that launcher.test pins against hooks/run.sh); every other tool, anything it cannot read, and any project that is a linked worktree (its scope lives in the main checkout, which the filter's walk up from the project need not reach), runs the guard — check: pre-guard.test.mjs parity table, launcher.test.mjs filter and timing cases — cite: hooks/run.sh:17-52, hooks/run.sh:61-63
- **ARCH-SAFETY-12** [decided] The sandbox settings block /craftsman:init offers MUST enable the sandbox and add permissions.ask rules only for what the sandbox cannot protect inside the project (sudo, force push, hard reset, git clean); it MUST NOT add `Bash(rm -r *)` or `Bash(rm -rf *)` asks, since deletes outside the project are the sandbox's (ARCH-SAFETY-01), and the merge never removes an ask rule already in the user's file — check: settings-merge.test.mjs asserts SANDBOX_BLOCK holds no rm ask and a pre-existing rm ask survives a merge; init.test.mjs asserts the preview lists no rm ask — cite: scripts/lib/settings-merge.mjs:8-11, scripts/lib/settings-merge.mjs:23-34
