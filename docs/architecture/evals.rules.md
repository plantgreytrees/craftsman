# ARCH evals — enforced rules

- **ARCH-EVALS-01** [decided] Behaviour evals MUST run on first-party `claude plugin eval` with cases under evals/ as prompt.md plus graders/*.md; a case.yaml is allowed only for `context` fields and MUST NOT carry `graders`; no third-party harness, npm dependency or `experimental.evals` manifest key — check: evals.test.mjs walks evals/ for only those files and rejects a `graders:` key in case.yaml; plugin.json has no `experimental` or `dependencies` key — cite: docs/architecture/evals.rules.md:11, docs/architecture/slim.rules.md:29
- **ARCH-EVALS-02** [decided] Every grader MUST be deterministic: type tool_used, tool_order, file_exists or regex; no llm or baseline grader — check: evals.test.mjs fails on any other `type:` in graders/*.md frontmatter — cite: docs/architecture/evals.rules.md:12
- **ARCH-EVALS-03** [superseded by ARCH-EVALS-08]
- **ARCH-EVALS-04** [decided] The suite MUST hold exactly one hook smoke case, tagged `hook`: it asks Claude to quote the `craftsman guards:` line its SessionStart hook injects, graded by a regex on last_message, with no tool grants; guard behaviour itself stays covered by scripts/*.test.mjs and MUST NOT be re-tested in evals — check: evals.test.mjs counts cases tagged `hook` = 1 and finds no `allowed_tools` beyond read-only in it — cite: scripts/session-context.mjs:303
- **ARCH-EVALS-05** [decided] Every documented suite run MUST pass `--ablation none`, `--max-cost-usd 5` and `--no-publish` and grant only the tools a case exercises; results stay in evals/results/, which .gitignore MUST list — check: evals.test.mjs asserts the .gitignore line and all three flags in the README run command — cite: docs/architecture/evals.rules.md:15
- **ARCH-EVALS-06** [decided] The suite MUST be run, with each case's score recorded in the release's CHANGELOG entry, before the stable branch is moved (ARCH-MOD-06) and after any trim under ARCH-SLIM-18; when `claude plugin eval` is unavailable the entry records "Evals: unavailable" with the error and stable may still move; it MUST NOT run as a CI gate — check: .github/workflows/ci.yml has no `plugin eval`; each release entry carries an Evals line — cite: README.md:421-430
- **ARCH-EVALS-07** [superseded by ARCH-EVALS-09]
- **ARCH-EVALS-08** [decided] The suite MUST hold one case named skill-fires-<name> with a `tool_used: Skill` grader for every skill directory under skills/ except language-aware-planning, which commands/plan.md names by path; a skill removed under ARCH-EVALS-10 takes its case with it (owner decision 2026-11-25, skill-description-rewrites) — check: evals.test.mjs maps each skills/ directory to its case and fails on a case with no skill — cite: scripts/evals.test.mjs:17,120-122
- **ARCH-EVALS-09** [decided] A skill that no command or agent names (by path or Skill call) and whose firing case passes fewer than 2 of 3 runs gets exactly one description rewrite, in order: (1) a ceiling run that temporarily copies the case prompt's key words into the description; if that also scores 0/3, the case design is fixed once (a fixture folder through case.yaml `context` plus read-only tools) and re-baselined before any rewrite; (2) one rewrite in imperative "Use when…" user-intent form inside the ≤110-char per-skill cap and the 4,500-char descriptions total, never through `when_to_use` or a raised cap; (3) a local held-out check of two fresh paraphrases and one should-not-fire near-miss, run outside evals/. The skill is kept only if it passes ≥2 of 3 on its case, ≥2 of 3 on each paraphrase and ≤1 of 3 on the near-miss (owner decision 2026-11-25) — check: the CHANGELOG entry records the baseline, ceiling, after and held-out scores per skill — cite: scripts/skills-vendored.test.mjs:38, scripts/descriptions.test.mjs:17
- **ARCH-EVALS-10** [decided] A skill that is not kept under ARCH-EVALS-09 is removed, never wired into a command or agent (the loop already enforces test-first at agents/implementer.md:24, root cause in commands/investigate.md and verification in the Stop gate): its skills/<name>/ directory, its evals/skill-fires-<name>/ case, its FILE_CAPS entry in scripts/doc-size-policy.mjs, its entries in scripts/skills-vendored.test.mjs and scripts/evals.test.mjs, and its README Layout mention all go in the same change — check: grep of the repo for the skill name finds only CHANGELOG and docs/ history — cite: scripts/doc-size-policy.mjs:21, README.md:562-563
