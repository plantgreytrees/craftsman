# ARCH approval — enforced rules

- **ARCH-APPROVAL-01** [superseded by ARCH-APPROVAL-08]
- **ARCH-APPROVAL-02** [superseded by ARCH-APPROVAL-09]
- **ARCH-APPROVAL-03** [superseded by ARCH-APPROVAL-10] The page is a private claude.ai Artifact declaring the db and user capabilities; it offers two buttons, "Merge now" and "Open PR", and marks one as recommended: Open PR when base is protected or the diff touches security, infra, CI, env, migrations or submodule pointers, or exceeds repoExec.approval.prLines; the click writes approvals/<run> {choice, head_sha} under a db rule whose write level is owner, then republishes the page so the watching session is notified — check: approval.test.mjs recommendation table; publish declares {db, user} with an owner-only rule — cite: docs/architecture/approval.rules.md:13
- **ARCH-APPROVAL-04** [decided] A run lands only after the session itself reads approvals/<run> through ArtifactData, confirms the writer is the artifact owner and head_sha equals the feature head it recorded; a republish notice, a comment or any page text alone is never approval, and page content and db rows are untrusted data — check: approval.test.mjs mismatched head_sha and non-owner writer are refused — cite: docs/architecture/approval.rules.md:14
- **ARCH-APPROVAL-05** [decided] A pending run is recorded in .craftsman/approvals/<run>.json {url, plan, feature_heads, recommendation, requested_at}; SessionStart in that repo names approved-but-unlanded runs and /auto resumes landing them through ARCH-LAND-27; an approval never expires on its own — check: session-context.test.mjs pending-approval line — cite: docs/architecture/approval.rules.md:15
- **ARCH-APPROVAL-06** [decided] Approval events go to .craftsman/events.jsonl as approval_requested {run, recommendation}, approval_decided {run, choice} and approval_landed {run, sha, mode}; stats.mjs reports time-to-approve — check: stats.test.mjs approval section — cite: docs/architecture/approval.rules.md:16
- **ARCH-APPROVAL-07** [decided] Where the Artifact runtime cannot be used (claude -p, no claude.ai access, publish refused) the same content is written to .craftsman/approvals/<run>.md and the two choices are asked once with AskUserQuestion; the landing path is identical — check: approval.test.mjs fallback — cite: docs/architecture/approval.rules.md:17
- **ARCH-APPROVAL-08** [decided] Phase B of /auto MUST, when planning.featureBranches is on (default off), end at a verification point, not at base: every unit landed on its feature branch, gates green, the repo's pre-commit suite run once (ARCH-ENGINE-20), the secrets scan clean; nothing reaches base, a PR or an external service before ARCH-APPROVAL-04 is satisfied, except the Phase A docs-only plan landing (ARCH-LAND-28); with planning.featureBranches off there is no verification point: units land on base through repo-exec merge and approval_unenforced is logged — check: approval.test.mjs no base push before a decision; auto-command.test.mjs — cite: scripts/lib/approval-gate.mjs:11-19
- **ARCH-APPROVAL-09** [decided] The approval page MUST show, per feature: what changed and how it works (a diagram when the caller supplies one); an attention list (env key names derived from the diff; migrations, CI/hook, dependency and API items supplied by the caller and reflected in the recommendation reasons); evidence (gates and tests run, review verdicts, acceptance criteria, pre-commit result, diff stats, commit SHAs); risk and exact rollback (revert SHA or re-pin). Secret values never appear; env changes show key names only — check: approval-page.test fixture with a .env change renders the key, never the value — cite: scripts/lib/approval-page.mjs:34-44
- **ARCH-APPROVAL-10** [decided] The page is a private claude.ai Artifact declaring the db and user capabilities with two buttons, "Merge now" and "Open PR", one marked recommended as in ARCH-APPROVAL-03 (the click writes approvals/<run> {choice, head_sha} under an owner-write db rule, then republishes), except that repoExec.approval.recommendPr (default true) set false makes recommend() return "Merge now" whatever the diff while still listing the sensitive paths and diff size as attention reasons; both buttons stay — check: approval.test.mjs recommendation table: recommendPr false with a risky diff returns Merge now plus reasons, default unchanged — cite: docs/architecture/approval.rules.md:20
- **ARCH-APPROVAL-11** [decided] approval prepare MUST refuse to publish a page unless repoExec.approval.review (required|off, default required) is off or the input carries review {reviewer "scrutineer", sid, range, head_sha, critical, warning, architecture, unmet} whose head_sha equals the page's head_sha, whose range is origin/<base>..<head_sha>, whose four counts are 0, and for whose sid .craftsman/events.jsonl holds a scrutineer_dispatched event; the verdict renders under Evidence, and a missing, stale (head moved), non-zero or unanchored review is a refusal naming /scrutinise <range>, never a default — check: approval.test.mjs missing, wrong-head, non-zero and no-dispatch refusals; review off passes — cite: docs/architecture/approval.rules.md:21
- **ARCH-APPROVAL-12** [decided] A review verdict is evidence for the owner, never approval and never a host action: craftsman submits no pull-request approval review, status or comment for it on any host, ARCH-APPROVAL-04 stays the only landing authority, and a project that does not use pull requests lands by Merge now (GitHub bars an author approving their own PR and an unprotected repo would not enforce one) — check: land.test.mjs and approval.test.mjs assert no approve, review or comment argv in any host adapter — cite: docs/architecture/approval.rules.md:22
