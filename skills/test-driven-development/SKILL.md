---
name: test-driven-development
description: Write the failing test first, then the minimum code. Use before new behaviour.
---

Adapted from obra/superpowers (MIT License). Standalone: needs no other plugin.

1. Write one test for the next behaviour; run it and watch it fail for the right reason.
2. Write the least code that makes it pass.
3. Run the whole suite; refactor only while green.
4. Never weaken, skip or delete a test to get green.
5. Repeat per acceptance criterion.
